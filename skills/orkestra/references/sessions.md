# Task sessions and recovery

Read before starting, resuming, handing off or reopening a worker/reviewer conversation. The coordinator owns dispatch and findings; workers return results without recursively delegating back.

## Bind the task

Extend the task's existing private ledger with one record per slice and peer role: persistent task/slice ID, human-readable name, coordinator tool and real conversation ID, assigned workdir, allowed writes, selected route/model/effort, exact peer session ID, status, process handle, last snapshot/result paths and acknowledged native-history cursor. Use trusted host metadata for IDs; an unknown ID stays unknown. A new caller chat does not imply a new task. Discover existing work before creating sessions; titles are hints, not unique identities. Separate parallel tasks and fresh review contexts deliberately, retaining parent/reason evidence. Each conversation has one active call or managed manual use.

Keep the canonical ledger and raw results in a durable private location outside disposable worktrees and published artifacts. Link its absolute path from the existing checkpoint; a project-local index is a link, not a second dispatchable record. Preserve existing native history, `CODEX_HOME` and `CLAUDE_CONFIG_DIR`; leave transcripts in their tools' native stores. Keep independent reviewers' earlier reports outside their readable packet until the initial review ends.

Start peers in the assigned project/worktree directory, then resume there. A packet directory or skill installation path does not choose the project. A worker may use a deliberately isolated worktree and a reviewer an immutable checkout; record that assignment explicitly. Within a paired Codex/Opus review, inherit the initiating session's current directory in both directions, as Duo requires.

For an actual Codex↔Opus read-only review, read [Duo conversation lifecycle](../../duo/references/conversations.md) and [transport](../../duo/references/opus-session.md), then use its dispatcher: shared `list/show`, canonical task IDs, cross-path duplicate prevention, explicit `handoff/fork`, managed `manual`, `sync/ack` and persisted native-result checks. Keep the same shared index across caller chats. Its executable transport remains specific to Codex/Opus at xhigh; builders and Astra/Fable roles use supported host tools with the same lifecycle recorded in this ledger. If a route cannot expose/reconcile native history or prevent concurrent use, report that coverage gap and serialize it manually; do not claim the Duo helper enforces it. Inspect installed CLI help before changing flags.

## Resume by identity

1. Resolve the canonical record by persistent task ID through the checkpoint or shared discovery index. Match coordinator identity, task/slice, peer role, workdir and intended source. Recency, `--last` and `--continue` do not establish that match. Ambiguous ownership or missing history needs resolution before dispatch; retain the old evidence.
2. Inspect status, exact native peer ID, last result and reviewed snapshot. Compare the snapshot with current work and retain only applicable evidence. A different coordinator needs explicit handoff after the old coordinator is idle, preserving peer IDs, scope/decisions and evidence. Revoke old dispatch ownership instead of impersonating it. Changing direction retains the old owner's native conversation as peer; a fresh caller's history is not silently merged with another conversation.
3. Read new native user/assistant turns since the acknowledged cursor, reconcile manual decisions and handoff context, then acknowledge the observed history head. Concurrent new messages require reading again. Resume the recorded peer from its workdir with stable model, effort, tools and scope. Send changed evidence and the focused request. Create a separate context only for explicitly separate work or independent initial review, recording its parent, reason and new ID.

For manual reopening, idle the coordinator and give the user the recorded directory plus the concrete managed manual command from Duo `show` when supported. Its command restores the recorded directory/config homes/shared index in a subshell; unknown owner models require an explicit actual model. It holds the canonical lock until the native CLI exits. Direct `claude --resume EXACT_ID`, `codex resume EXACT_ID`, desktop interaction and other routes bypass that lock; explicitly serialize their manual/automatic use. Restore recorded model/effort/permissions and reconcile new native turns before dispatch resumes. Native history, exact-ID reopening, picker visibility and desktop sidebar visibility are separate claims; index labels do not prove native titles. Report only what was observed.

## Interrupted or missing results

Track a process/session handle and a bounded deadline. Disconnect stdin for unattended CLI calls unless it deliberately carries the prompt. Keep the outer tool deadline longer than a child dispatcher's cleanup deadline, or background it and track completion. On timeout/interruption, stop only that dispatch's tracked process group through the supported host mechanism and retain output/IDs. A timeout, interruption, empty output, wrong session or missing completion/persistence evidence leaves the call held; inspect the native session and process before recovery. Check for a live peer before starting another call. Do not reset a held record or silently replace missing history.

For independent initial reviews, launch the selected peers concurrently from the same frozen source, then collect each peer independently. For local CLI routes use [parallel_reviews.py](../scripts/parallel_reviews.py). Supply a private JSON manifest:

```json
{"jobs": [{"id": "reviewer", "command": ["/absolute/provider-cli", "supported-arguments"], "cwd": "/absolute/project", "timeout_seconds": 600, "session_id": "EXACT_NATIVE_ID"}]}
```

Run `python3 /path/to/installed/orkestra/scripts/parallel_reviews.py --manifest PRIVATE.json --output NEW_PRIVATE_DIRECTORY`. Commands receive no stdin; use supported prompt arguments or file attachments. Empty arguments are preserved (for example Claude's `--tools ""`). Inherit native accounts without putting credentials in the manifest. Keep existing session locks; the runner rejects duplicate IDs within a batch but does not lock across separate batches. When a provider assigns a fresh ID only after launch, replace `session_id` with `"new_session": true`; never fabricate an ID. Collect the real ID from native output/history into the canonical session record before any follow-up. Preallocated Claude IDs can use `session_id` from the first launch.

Each peer gets separate stdout, stderr and status files, a deadline measured from its own launch, and an immediate completion event. A launch failure or timeout does not discard another peer's result. Cleanup terminates the managed process group, including descendants after the wrapper exits. `cleanup_failed` preserves the PID and requires host inspection before another call; SIGKILL/host shutdown may leave a running record. Keep the outer deadline above the longest call plus cleanup, or supervise the runner in a background terminal. A nonzero runner exit means at least one transport failed; inspect each result separately.

A zero exit is only a transport outcome. Verify provider completion, nonempty answer, exact native session/persistence, source identity and actual model/effort before counting coverage. The runner does not validate those provider-specific facts, parse usage, or automatically resume a held call. Its session fields are caller assertions until reconciled with native evidence.

For large planning requests, do not send a whole source archive and demand a complete, detailed plan in one high-effort answer. First request a bounded plan outline against a compact contract/ownership map; then request source-grounded sections with the smallest complete relevant evidence, recording which frozen files each section covers; finally integrate and check dependencies. Each call has its own justified deadline and a required concrete deliverable. Keep the same exact peer session for dependent sections; a new initial review context remains independently fresh. Do not call partial thinking output or an outline a completed plan. If a call times out, retain its native ID and partial evidence, inspect whether a process is still live, and resume only the missing section with changed scope or evidence. Merely raising the timeout or repeating the same oversized prompt does not change the failure cause.

Complete unaffected work. Retry when the missing prerequisite changes; a provider-reported temporary failure with retry guidance permits one bounded retry within budget. Repeated timeouts alone supply no new evidence. When a spending limit exists, record it and known/unknown usage before dispatch; new calls and retries stay within remaining authorization. Available account credit does not increase that allowance. Native session reuse preserves history, but a cache hit requires actual usage telemetry. Keep the shared prefix stable where useful and avoid paid keepalive calls. Tmux, if already available, can preserve a terminal process across disconnects; it does not preserve a process through host shutdown or extend cache TTL.

## Accept the result

Record requested and observed route/model/effort, exact peer ID, packet/source identity, exit/error status, final completion and nonempty result. Label unreported runtime metadata unknown. Helper-managed Claude/Codex reviews require new matching assistant text in the exact native transcript; Codex also requires matching session and completion events. A prompt's requested model, exit zero or an old transcript alone is insufficient. The coordinator still verifies snapshot contents, source/financial scope and returned claims; a session helper does not enforce these.
